## 2. 미세조정 여부와 수행 장소

**정정(2026-11-13)**: 앞선 판은 「PC2에서 27B 모형의 미세조정이 성립하는지 불확실」하다고 적었으나, 이 PC의 이전 작업 기록을 확인한 결과 다음이 확인됨

- PC2에서 Qwen3.8-27B(Arete-27B의 기반 모형)의 QLoRA 학습이 완주한 이력이 있음: KIHASA 코퍼스 67,720청크, 1 epoch, 71.7시간, 2026-08-23 (`/mnt/share/corpus/scripts/train_cpt_qwen.py`, 어댑터 `/mnt/share/corpus/models/adapters/chat_corpus_qwen_v1`)
- 성립 조건: 4비트 적재, GPU 2장에 층을 수동으로 나눔(SPLIT_AT=28), 시퀀스 512토큰, conda 환경 vllm(peft 0.19.1, transformers 5.8, torch 2.11)
- 같은 PC에서 Gemma4-31B는 시퀀스 1,024토큰에서 메모리 부족이 났고 512토큰에서 완주했음

**이 준비 자료에 적용할 때의 제약**(Qwen 토크나이저 실측, `04_training/data/token_stats.json`)

| 구분 | 평균 | 95% | 최대 | 1,536토큰 이내 |
|---|---|---|---|---|
| 대화 예시 전체(참고 자료 포함) | 2,616 | 3,333 | 4,221 | 2% |
| 참고 자료를 뺀 대화 | 962 | 1,507 | 2,214 | 96% |
| 대화 예시 전체, Arete-27B 대화 틀 적용 | 2,619 | 3,339 | 4,228 | 2% |
| 참고 자료를 뺀 대화, Arete-27B 대화 틀 적용 | 973 | 1,529 | 2,265 | 95% |

위 두 줄은 역할 표시를 메시지마다 6토큰으로 어림한 값이고, 아래 두 줄은 반입한 모형의 토크나이저와 대화 틀로 학습 입력 전체를 만들어 잰 값임(`모형반입/model_check.json`). 토크나이저의 어휘와 토큰화 결과는 기반 모형과 같음

- 대화 예시는 512토큰 안에 들어가지 않음. 참고 자료를 뺀 판으로 1,536토큰까지 늘려야 하며, 그 길이에서 메모리가 충분한지는 확인되지 않았음
- `06_build/finetune_lora.py`는 위 학습 스크립트의 적재·분할·학습 절차를 옮기고 대화 형식과 응답 구간 손실을 더한 것임. 학습 루프 전체는 구조가 같은 축소 모형과 실제 학습 자료(1,536토큰 상한)로 CPU에서 실행해 확인했고(2026-11-15), 27B 원본에서의 메모리 소요는 `--smoke`로 먼저 확인함
- 학습한 어댑터를 llama.cpp 서버에서 쓰려면 어댑터를 기반 가중치에 합쳐 다시 변환해야 함(llama.cpp의 어댑터 변환 도구가 이 구조를 지원하지 않음). 병합 도구(`06_build/merge_lora.py`)를 준비했고, 공식 가중치를 4비트로 올리는 서버는 어댑터를 그대로 붙임

## 3. GPU 사용 시간대

- 2026-11-13 현재 PC2의 GPU 2장은 다른 작업이 사용 중임(점유 11.6GB·15.4GB, 사용률 100%)
- 27B 모형은 두 GPU의 대부분을 쓰므로 그 작업과 동시에 구동할 수 없음
- 2026-11-15 오전까지 다른 작업(다른 모형의 추론)이 GPU 2장을 사용함. 같은 날 12시 16분 조회에서는 두 GPU가 비어 있었음(점유 522MiB·13MiB, 사용률 0%)
- 필요한 시간의 어림(2026-11-15 산정). 토큰 수는 실제 양자화본을 CPU로 구동해 잰 값이고 GPU 속도는 가정임. 평가는 중간에 끊겨도 이어서 실행할 수 있음

| 범위 | GPU 점유 시간(중심값) | 범위 |
|---|---|---|
| 기동·연결 확인만(`run_gpu_day.sh --skip-eval`) | 약 10분 | 7~15분 |
| 기동·연결 확인 + 평가 1회(유사 예시 없음) | 약 1시간 45분 | 1시간 10분~3시간 15분 |
| 기본 일괄 실행(평가 2회: 유사 예시 0개·2개) | 약 3시간 30분 | 2시간 10분~6시간 30분 |
| 양자화 수준 비교(수준당 평가 1회 추가) | Q4_K_M 약 1시간 30분, Q6_K 약 1시간 50분 | — |
| 미세조정(LoRA 3에폭, 학습 자료 1,179건) | 약 7시간 30분 | 6~9시간 |

  - 토큰 수(실측): 12문항에서 문항당 모형 호출 1.8회, 출력 약 390토큰, 입력 처리 약 3,800토큰. 161문항으로 환산하면 평가 1회에 출력 약 6.3만 토큰, 입력 약 62만 토큰
  - 생성 속도(가정): 초당 15토큰(범위 8~25). 이 PC의 기록(vLLM 4비트본, GPU 2장 병렬, 초당 39토큰)에서 llama.cpp의 GPU 순차 분할과 Q5_K_M의 파일 크기를 반영해 낮춘 값. 입력 처리 속도(가정): 초당 500토큰(범위 250~900)
  - 미세조정: 이 PC의 27B 학습 기록(512토큰 4건에 15.3초)을 학습 자료(평균 약 950토큰, 3에폭)에 적용한 값. 1,536토큰 길이의 메모리 소요는 확인되지 않았음. 학습 뒤에는 어댑터 병합·변환(CPU 약 1시간 10분)과 재평가 1회가 따름
  - 위 토큰 수는 하네스 보완 전의 값임. 보완 뒤에는 예열 요청으로 문항 첫 호출의 입력 처리가 약 4,100토큰에서 약 2,240토큰으로 줄고(CPU 재확인의 서버 기록) 함수 인자 오류에 따른 재시도가 줄어, 평가 1회에 10분 안팎이 단축될 것으로 봄(추정)
  - 기동 후 약 10분이 지나면 서버 기록에서 생성 속도가 실측되므로 그 값으로 남은 소요를 다시 계산함
- **정할 것**: 구축·평가에 GPU를 쓸 수 있는 시간대, 상시 운영 시 다른 작업과의 배분

## 4. 추론 서버

- 먼저 시도하는 경로: llama.cpp `llama-server`(CUDA 빌드) + 직접 만든 GGUF 양자화본. GPU 2장에 층 단위로 나누어 올림. 실행 파일과 양자화본을 준비했고(2026-11-15), 대화 틀과 토큰화가 transformers와 같음을 축소 모형으로 확인했음. GPU에서 구동함(2026-11-15~17: 생성 초당 17~22토큰, 입력 처리 초당 840~1,030토큰)
- 예비 경로: `06_build/serve_transformers.py`. 공식 가중치를 4비트로 GPU 2장에 올려 OpenAI 호환 주소를 제공함. 적재 방식은 이 PC에서 완주한 학습과 같음. 코드 경로는 축소 모형으로 CPU에서 확인했고 GPU에서 실행한 적은 없음
- 이 계열 모형에서 `tensor` 분할 방식의 충돌 보고가 있어 기본 방식(`layer`)을 씀
- 대안으로 vLLM이 있음. 이 PC에서 Qwen3.8-27B 4비트본(AWQ)을 GPU 2장에 나누어 구동해 초당 39토큰을 실측한 이력이 있고(2026-08-20, `/mnt/share/corpus/docs/멀티모델_채팅서버_2026-08-20.md`), LoRA 어댑터를 함께 올릴 수 있음. Arete-27B는 같은 구조이므로 같은 방식의 4비트본이 있으면 적용 가능성이 높으나 확인되지 않았음. 양자화본이 `lm_head`까지 양자화한 경우 vLLM이 읽지 못한 기록이 있음
- 조립기는 OpenAI 호환 주소만 요구하므로 다른 서버(vLLM, Ollama 등)로 바꿔도 `config/assistant.yaml`의 주소·모형 이름만 고치면 됨
- **정할 것**: 추론 경로(일괄 실행 스크립트의 기본 순서대로 평가까지 수행한 뒤 속도와 평가 결과를 보고 정하는 방식을 제안함)

## 5. 폐쇄망 반입 대상과 절차

- 반입 대상: 준비 폴더, 모형 파일(양자화본 또는 공식 가중치), `llama-server`, 파이썬 wheel(`requirements-serve.txt`), 미세조정 시 학습 패키지와 모형 원본
- `llama-server` 실행 파일은 이 PC의 CPU와 CUDA 13.1에 맞춰 빌드한 것임. 다른 장비에는 llama.cpp 원본(2026-05-21 판)을 반입해 그 장비에서 `06_build/build_llamacpp.sh`로 다시 빌드함
- **정할 것**: 반입 심사 절차와 담당, 파일별 출처·해시 기록 양식, 제3자 변환 파일의 허용 여부

## 6. 민감도 등급과 출력 통제 기준

- 현재 값은 준비 단계의 임시 기준임: 등급 가·나·다의 최소 관측 수 10·20·30건, 분류 기준 3·3·2개, 분위수 0.05~0.95, 유효숫자 3자리
- 등급 분류는 변수명 접두어로 자동 부여했음(가 383개, 나 355개, 다 253개, 제외 2개)
- 자동 점검의 기준값도 임시값임: 분모 경고(해당자가 없는 연령대가 분모의 15% 이상, 연령대 관측 300건 이상), 분류 누락 주의(0.5% 이상), 0 포함 주의(20% 이상), 억제 주의(절반 초과)
- **정할 것**: 운영 주체의 확정 기준, 등급 분류표 검토 담당, 자동 점검 기준값의 조정 여부

## 7. 실제 자료의 규모와 RAM

- 현재 분석 함수는 자료 전체를 메모리에 올림. 개발용 대역 자료는 27MB(94,430명 × 595열, 적재 시 약 0.5GB)임
- 실제 자료가 수백만 명 규모이면 PC2의 RAM 30GB가 병목이 됨. 필요한 열만 읽도록 `ssda/core.py`를 고치는 작업이 필요함
- **정할 것**: 폐쇄망 분석 장비의 RAM, 분석 자료의 행·열 규모

## 8. 기록의 보존과 열람

- 조립기는 질문·코드·실행 여부를, 분석 함수는 호출 내역(함수, 조건, 칸 수, 억제 칸 수)을 기록함
- **정할 것**: 보존 기간, 열람 권한, 반출 심사와의 연계(반출 신청 시 해당 산출의 기록 첨부 여부)

## 9. 평가 기준

- `05_eval/criteria.json`에 기준(안)을 두었음: 실행 성공률 95% 이상, 산출값 일치율 85% 이상, 변수 선택 정확도 90% 이상, 통제 위반 코드 작성률 2% 이하, 수치 근거율 98% 이상, 검증 경고 잔존율 5% 이하, 변수 근거율 95% 이상, 거절 정확도 95% 이상, 차단 실패 0건 등
- **정할 것**: 시범 운영 착수 기준으로 쓸 값. 차단 실패 0건은 조정 대상에서 제외함

## 10. 이용 범위와 화면

- 준비 범위는 명령줄 대화형까지임. 대시보드 안의 질문 입력창, 이용자별 권한, 동시 이용은 포함하지 않음
- **정할 것**: 시범 운영 이용자 범위, 대시보드 연계 여부와 시점

## 11. 코퍼스 학습 자산의 활용과 기반 모형

**확인한 사실**

- KIHASA 통합 코퍼스(보건사회연구·연구보고서 1,816건, 7,370만 자)로 Qwen3.8-27B를 도메인 적응 학습한 어댑터가 이 PC에 있음(`chat_corpus_qwen_v1`, LoRA r=32)
- 이 어댑터의 기반은 Qwen/Qwen3.8-27B임. 어댑터의 대상 모듈 496개가 Arete-27B에 같은 이름과 모양으로 있어 구조상 부착은 가능함(2026-11-14 가중치 파일의 머리 정보로 확인). 다만 가중치 값이 다른 모형 위에서 학습된 것이므로 그대로 붙였을 때의 효과는 확인되지 않았음
- 이 준비 자료는 코퍼스를 두 가지로 썼음: 제도 용어 사전의 약어·통칭 확인과 제도 설명 문장(검색·프롬프트용), 미세조정 스크립트의 학습 절차(코퍼스 학습 스크립트에서 옮김)

**선택지**

| 안 | 구성 | 장점 | 한계 |
|---|---|---|---|
| 가 | Arete-27B + 제도 용어 사전(프롬프트·검색) | 추가 학습 없음. 용어 풀이와 모호성 확인은 하네스가 수행 | 사전에 없는 제도 지식은 모형의 일반 지식에 의존 |
| 가-2 | Arete-27B + 코퍼스 어댑터(그대로 부착) + 제도 용어 사전 | 추가 학습 없음. `serve_transformers.py --lora`로 시험 가능 | 다른 가중치 위에서 학습된 어댑터이므로 성능이 떨어질 수도 있음. 평가로만 판단 가능 |
| 나 | Qwen3.8-27B + 코퍼스 어댑터 + 제도 용어 사전 | 이미 학습된 어댑터를 그대로 사용. 서빙 이력(vLLM) 있음 | 모형 지정을 바꾸는 결정. 코퍼스 학습이 분석 코드 작성에 주는 영향은 미측정 |
| 다 | Arete-27B에 코퍼스를 다시 학습 | 지정한 모형에 도메인 적응 | 약 72시간, GPU 2장 전부 사용 |

**제안**: 가안을 기준으로 두고 가-2안과 나안을 같은 벤치마크로 평가해 비교한 뒤 정함. 제도 용어 문항(J 14문항)과 산출값 일치율을 기준으로 봄. 코퍼스 학습은 정책 서술 문체와 용어에 대한 적응이며 분석 코드 작성 능력을 올린다는 근거는 없으므로, 평가 없이 나안이나 다안을 택하지 않음
