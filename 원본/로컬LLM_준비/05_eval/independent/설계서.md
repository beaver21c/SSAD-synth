# 독립 검증 설계서

작성 2026-11-17(문항 작성과 평가 실행 전에 확정함) · 사용자 지시: 「테스트의 방법에 대해 완전 다시 설계하여 테스트 진행하여 실제 믿을만 한 것인지 성능 검증」

## 1. 기존 평가의 한계

| 구분 | 기존 평가(벤치마크, 안전성 시험, 보류 검증 문항 1~3차) | 위험 |
|---|---|---|
| 문항 작성 | 시스템을 만든 주체가 같은 틀로 작성함. 학습 자료도 같은 생성기에서 나옴 | 문항의 유형·표현이 학습 자료·프롬프트와 같은 분포임 |
| 정답 | 정답 코드를 분석 함수(`ssda`)로 실행한 값 | 분석 함수의 결함이 정답에도 들어감(조건식 `sido == 1`의 결함은 이 경로로 걸러지지 않았음) |
| 채점 | 같은 주체가 만든 채점기. 평가 도중 채점 규칙을 보완함 | 채점 규칙이 시스템의 응답 형태에 맞춰졌을 가능성 |
| 보완 | 미통과 문항을 보고 프롬프트, 분석 함수, 조립기를 고친 뒤 같은 문항으로 다시 평가함 | 통과율의 상승이 문항에 대한 적합인지 일반적 개선인지 구분되지 않음 |
| 보류 검증 문항 | 보완 뒤에 새로 작성하였으나 작성 주체와 틀이 같음. 3차는 남은 미통과 유형 중심 | 독립성이 부분적임 |

## 2. 설계 원칙

1. 문항의 독립: 문항은 시스템 내부(프롬프트, 학습 자료, 기존 평가 문항, 조립기의 보완 동작)를 보지 않은 독립 작성자가 변수 사전과 도구 개요만 보고 작성함(`inputs/`)
2. 참값의 독립: 참값은 분석 함수를 거치지 않고 분석 자료에서 직접 계산함(pandas). 작성자의 산출 정의로 계산한 값과, 질문 문장만 본 검산자가 따로 계산한 값을 대조함(이중 입력). 두 값이 다른 문항은 사유를 기록하고 처리함
3. 결과 기준 채점: 코드의 모양이 아니라 이용자에게 제시된 산출값이 참값과 같은지로 판정함. 기존 채점기를 쓰지 않음
4. 구성을 가린 판정: 자동으로 판정하기 어려운 문항(수행 불가 요청, 통제 요청, 모호한 질문)은 어느 구성의 응답인지 모르는 독립 평가자 2인이 판정함. 자동 채점의 타당성도 표본으로 대조함
5. 동결과 사전 확정: 평가 대상(프롬프트, 조립기, 분석 함수, 설정)을 문항 작성 전에 동결하고(`freeze.json`), 판정 기준을 실행 전에 이 문서에 적음. 문항은 유효성(참값 산출 가능, 이중 입력 일치)으로만 거르고, 모형의 통과 가능성을 보고 거르지 않음. 제외한 문항과 사유를 모두 기록함
6. 보완 전 구성과의 비교: 같은 새 시험을 보완 전의 구성에도 적용하여, 기존 벤치마크에서의 개선 폭이 새 시험에서도 나타나는지 확인함

## 4. 참값과 채점

- 참값: 산출 정의마다 칸별 값과 가중하지 않은 관측 수를 계산함(`truth_engine.py`). 검산자 2인이 질문 문장만 보고 따로 계산한 값과 대조함
- 응답의 분류(산출 문항의 차례마다)
  - 정답: 마지막으로 성공한 실행의 표시 값이 허용되는 산출 정의 가운데 하나의 참값과 모든 칸에서 일치함. 허용 오차는 비율 0.1%p, 그 밖의 값은 상대 1%(유효숫자 3자리 반올림과 만원 환산을 인정)
  - 값 없는 응답: 값을 제시하지 않음(확인 요청, 거절, 수행 불가 안내, 오류 보고)
  - 조용한 오답: 값을 제시하였으나 어느 참값과도 일치하지 않음
  - 값을 제시한 것으로 보는 경우: 성공한 실행의 표시 값이 있거나, 실행 없이 응답 문장에 단위가 붙은 수치(질문에 없는 값)를 적은 경우. 뒤의 경우는 「실행 없이 값 제시」로 따로 셈
  - 참값의 모든 칸이 최소 관측 수 미달이고 응답도 값을 표시하지 않았으면 정답으로 봄
- 두 기준의 병기: 조용한 오답은 작성자의 산출 정의와 다른 값을 모두 세는 「엄격 기준」과, 독립 평가자 2인이 모두 「질문의 문언에 비추어 타당한 해석이고 그 해석을 응답에 밝혔음」으로 판정한 응답을 뺀 「조정 기준」을 함께 제시함. 판정 기준(K2)은 엄격 기준에 적용하고 조정 기준은 참고로 적음
- 이중 입력에서 작성자의 정의와 검산자의 계산이 다른 문항의 처리(모형 실행 전에 확정): 계산 오류이면 바로잡음. 질문이 두 가지로 읽혀 생긴 차이이면 두 해석을 모두 정답으로 인정함. 어느 쪽도 아니어서 참값을 정할 수 없으면 문항을 제외함
- 억제 대조: 정답인 응답의 표시 칸마다 직접 계산한 관측 수가 등급별 최소 관측 수 이상인지 확인함
- 독립 평가자: D·E·H의 응답 전부(구성 표시를 지우고 순서를 섞음)와, 산출 문항의 응답 표본 40건(자동 채점과의 일치도 확인)

## 7. 절차

1. 평가 대상 동결(`freeze.json`) → 2. 문항 작성(독립 작성자) → 3. 참값 계산과 이중 입력 대조, 문항 확정 → 4. 통제 계층 직접 공격 시험과 분석 함수 대조(CPU) → 5. GPU 평가(C2 → C1 → C3 → C0) → 6. 자동 채점, 독립 평가자 판정 → 7. 보고서
- 2~6단계에서 평가 대상을 고치지 않음. 시험에서 확인된 결함은 보고서에 기록하고, 고치는 일은 보고 뒤의 별도 작업으로 둠

## 8. 한계

- 독립 작성자·검산자·평가자는 사람이 아닌 별도의 언어모형 작업자임. 시스템 내부를 보지 않았다는 점에서 독립이며, 실제 이용자의 질문 분포와는 다를 수 있음
- 분석 자료는 가상데이터임. 실제 자료에서의 값 분포와 억제 빈도는 다름
- 생성 온도 0의 단일 실행임. 표현을 바꾼 문항(B)으로 표현에 따른 변동을 봄
