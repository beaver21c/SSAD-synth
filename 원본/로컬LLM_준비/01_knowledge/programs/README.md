# 제도 용어 사전 안내

작성 기준일 2026-11-13

## 1. 목적

- 이용자는 변수명이 아닌 제도명·약어·통칭으로 묻는다(「국기초 수급률」「건보 본인부담금」「EITC 대상」). 모형이 이 말을 정식 명칭, 구성 급여, 자료의 변수에 연결하도록 하는 자료임
- 여러 급여나 내역을 묶어 부르는 말은 무엇을 가리키는지 정해져 있지 않은 경우가 많음. 그런 말에는 되물을 내용 또는 기본 해석을 사전에 적어 두고, 하네스가 질문마다 확인함

## 2. 구성

| 파일 | 내용 |
|---|---|
| `glossary.yaml` | 사전 원본(사람이 고치는 파일). 항목 44개, 용어 207개, 변수 190개 |
| `build_glossary.py` | 변수 대조, 조건식·합계 확인, 코퍼스 대조를 거쳐 아래 파일을 만듦 |
| `glossary.json` | 하네스(`06_build/terms.py`)가 읽는 사전 |
| `glossary_cards.jsonl` | 검색 색인에 들어가는 「제도 설명」 카드 |
| `glossary_report.json` | 약어·통칭의 코퍼스 사용 빈도, 코퍼스에서 고른 설명 문장, 코퍼스에서 확인되지 않은 약어 |

항목 구성: 제도 28개, 급여 2개, 용어 14개. 되묻는 항목(ask) 17개, 기본 해석으로 진행하는 항목(assume) 6개, 자료에 없는 항목(absent) 1개(낱말 17개), 확인이 필요 없는 항목 20개.

## 3. 항목의 내용

| 항목 | 뜻 | 예(국민기초생활보장제도) |
|---|---|---|
| `name`, `aliases` | 정식 명칭과 약어·통칭 | 국민기초생활보장, 기초생활보장, 국기초, 기초보장, 기초생보, 기초수급 |
| `desc` | 제도 설명(자료 기준연도 2022년). 현행 선정 기준·급여액은 적지 않음 | 맞춤형 급여 개편 이후 급여별 선정 기준이 따로 있음 |
| `target` | 수급률의 분모로 삼을 대상 | 전체 인구 |
| `parts` | 구성 급여와 각 급여의 변수 | 생계급여(nbls_live_yn1), 의료급여(nbls_medi_yn1), 주거급여(nbls_house_yn1), 교육급여(nbls_edu_yn1) |
| `union` | 「하나라도 해당하는 사람」의 조건식 | 네 급여의 수급 여부를 or 로 묶은 식 |
| `sum` | 「내역을 합한 금액」에 쓸 변수 묶음 | (본인부담금) 외래 nhi_out_fee + 입원 nhi_in_fee |
| `ambiguity` | 내역이 없을 때의 처리: `policy`(ask·assume·absent), `ask`(되물을 내용), `default`(기본 해석), `resolvers`(이 낱말이 있으면 내역이 정해진 것으로 봄) | ask: 어느 급여인지, 하나라도 받는 사람 기준인지, 급여별로 각각 볼지 |

## 4. 코퍼스와의 관계

- 근거: KIHASA 통합 코퍼스(`/mnt/share/corpus`, 판 20260701.5, 보건사회연구와 KIHASA 연구보고서 1,816건, 국문 청크 67,902개)
- 약어·통칭은 코퍼스에서 실제로 쓰이는지 빈도를 확인해 수록함. 예: 기초보장 1,562회, 기초수급 141회, 국기초 83회, 기초생보 16회, 건보 358회, EITC 178회
- 코퍼스에서 확인되지 않은 약어 7개(국취제, 산재 연금 등)는 현장 통칭으로 판단해 수록했으며 `glossary_report.json`에 따로 적혀 있음
- 제도의 뜻을 설명하는 문장을 코퍼스에서 1개씩 골라 16개 항목의 카드에 실었음. 고른 문장을 사람이 확인해 연혁·조사 설명·법조문이 뽑힌 항목은 제외함
- 변수 대응은 코퍼스가 아닌 코드북에서 온 것임. 코퍼스의 일반적 뜻과 자료의 범위가 다른 경우에는 설명에 차이를 적었음. 예: 본인부담금은 일반적으로 비급여까지 포함하는 뜻으로도 쓰이나 자료에는 법정 본인부담금만 있음
- 코퍼스 전체를 모형에 학습시키는 방법(도메인 적응 학습)은 별도의 선택지임. `결정필요사항.md` 2번과 11번 참조

## 5. 하네스에서의 쓰임

| 단계 | 처리 |
|---|---|
| 질문 접수 | 질문에서 제도명·약어를 찾음(긴 용어 우선). 찾은 항목의 「제도 설명」 카드를 참고 자료 앞에 붙이고, 정식 명칭과 구성 급여 이름으로 변수 카드 검색을 넓힘 |
| 내역 확인 | 묶어 부르는 말에 내역이 없으면 「용어 확인」을 질문 바로 앞에 붙임: 되묻게 함(ask), 기본 해석으로 진행하고 가정으로 밝히게 함(assume), 자료에 없음을 알리게 함(absent) |
| 실행 후 | 되묻지 않고 코드를 실행했으면 「[검증 결과]」에 용어 주의를 넣고, 검증 요약에 어떤 변수로 해석했는지 표시함 |
| 다음 질문 | 되물은 용어는 다음 질문에서 내역이 정해졌는지 다시 확인함 |

변수 찾기나 제도 설명을 요청하는 질문(「어떤 급여가 있는지」「변수가 무엇인지」)에는 내역 확인을 하지 않음.

## 6. 고치는 법

```bash
# glossary.yaml 을 고친 뒤
PYTHONPATH=02_library SSDA_DATA=<분석 자료> .venv/bin/python 01_knowledge/programs/build_glossary.py
.venv/bin/python 06_build/retriever.py build
PYTHONPATH=02_library SSDA_DATA=<분석 자료> .venv/bin/python 04_training/generate.py      # 참고 자료에 카드가 들어가므로 학습 자료도 다시 만듦
.venv/bin/python 06_build/retriever.py build && PYTHONPATH=02_library .venv/bin/python 04_training/validate.py
```

- 새 약어를 넣을 때는 다른 낱말 안에 들어 있는 글자열인지 확인함. 「고보」는 「국고보조」 안에, 「국연」은 다른 기관명 안에 들어 있어 제외했음
- 항목 이름이 흔한 낱말이면 `match_name: false`로 두고 통칭으로만 찾게 함(「소득」)
- 질문이 되물을 필요가 없는데 되묻게 되면 그 낱말을 `resolvers`에 추가함. 검증기의 V11 과 벤치마크의 J 문항으로 확인함
- 실제 자료로 전환해 변수 구성이 달라지면 변수 대조에서 중단되므로 사전의 변수 이름을 먼저 맞춤
