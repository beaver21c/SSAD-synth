# 프롬프트 조립 규칙

- 한 차례의 대화는 `system`(system_prompt_short.md 또는 system_prompt.md) → `user`(user_turn.md) → `assistant`(분석 계획 + 코드) → `user`(tool_result.md) → `assistant`(결과 + 유의 사항)의 순서임
- `{context}`에는 검색기가 찾은 문서를 넣음: 변수 카드 5개, 문서 카드 2개, 규칙 카드 1개(각 카드는 「■ 제목」 다음에 본문). 길이 한도는 카드당 500자
- 실행 결과는 모형별 도구 호출 형식에 의존하지 않도록 `user` 역할의 「[실행 결과]」 문단으로 넣음. 그림이 저장되면 `{figures}`에 「저장된 그림: 파일명」을 적음
- 오류가 나면 `{error}`에 「오류: 메시지」를 적어 돌려주고, 한 질문에서 코드 실행은 오류 수정 재시도를 포함해 4회까지 허용함(`config/assistant.yaml`의 `run.max_steps`)
- 실행에 성공하면 「[실행 결과]」 다음에 「[검증 결과]」를 붙임. 실행기가 집계 결과마다 자동 점검한 내역이며(`ssda.verify`), 한 줄에 결과 이름·판정·억제 칸 수·전체 값을 적고 경고·주의·참고를 그 아래에 적음. 문단은 `ssda.verify.tool_message()`가 만들며 조립기와 학습 자료 생성기가 같은 함수를 씀
- 없는 변수나 값이 없는 변수를 쓴 코드는 실행하지 않고 「오류: 없는 변수: … 비슷한 이름: …」으로 돌려보냄
- 마지막 응답의 「결과」에 실행 결과에 없는 수치가 있으면 `user` 역할의 「[검증 결과]」 문단으로 다시 작성을 요청함(1회, `verify.answer_retries`)
- 이용자에게 보여 주는 「검증 요약」은 모형이 쓰지 않고 하네스가 만들어 응답 뒤에 붙임
- 미세조정 없이 쓸 때는 `{context}` 끝에 「■ 비슷한 질문의 처리 예」 카드를 0~3개 덧붙일 수 있음(`prompt.n_examples`, 학습 분할에서만 검색)
- 후속 질문에는 이미 보여 준 카드를 다시 넣지 않으며, 새로 찾은 카드가 없으면 `[질문]`만 보냄
- 학습 자료(04_training)와 평가(05_eval), 구축 스크립트(06_build/assistant.py)는 모두 이 규칙을 따름
